RouteMind - Quick Setup Guide
=============================

STEP 1: Configure AWS Credentials
----------------------------------
nano .env

Add these lines:
AWS_REGION=us-east-2
AWS_ACCESS_KEY_ID=AKIA...your_key_here
AWS_SECRET_ACCESS_KEY=your_secret_key_here

Save and exit (Ctrl+X, Y, Enter)


STEP 2: Restart Services
-------------------------
docker-compose down
docker-compose up -d


STEP 3: Wait for Database (30 seconds)
---------------------------------------
sleep 30


STEP 4: Seed Sample Data
-------------------------
docker-compose exec routing-service python seed_simple.py


STEP 5: Test
------------
bash test_api.sh


TESTING WITHOUT AWS (AI Features Disabled)
===========================================
If you don't have AWS credentials yet, the system will still work:
- Route optimization: ✅ Works (uses OR-Tools)
- Distance calculation: ✅ Works
- Re-planning: ✅ Works
- AI explanations: ❌ Will show fallback text instead

The AI is only used for generating human-readable explanations.
The core routing algorithm (OR-Tools) doesn't need AWS.


WHAT EACH AWS CREDENTIAL DOES
==============================
AWS_REGION: Which AWS region to use (us-east-2 recommended)
AWS_ACCESS_KEY_ID: Your AWS access key
AWS_SECRET_ACCESS_KEY: Your AWS secret key

These are needed ONLY for AI explanations via AWS Bedrock (Kimi K2.5 model).


HOW TO GET AWS CREDENTIALS
===========================
1. Log into AWS Console
2. Go to IAM → Users → Your User
3. Security credentials tab
4. Create access key
5. Copy the Access Key ID and Secret Access Key
6. Add to .env file


BEDROCK ACCESS
==============
You also need Bedrock access in your AWS account:
1. AWS Console → Bedrock
2. Model access (left sidebar)
3. Request access to "Kimi K2.5" model
4. Wait for approval (usually instant)


MANUAL TEST COMMANDS
====================
# Test without AI
curl -X POST "http://localhost:8002/api/v1/optimizer/optimize?hub_id=1&use_ai_explanation=false"

# Test with AI (needs AWS credentials)
curl -X POST "http://localhost:8002/api/v1/optimizer/optimize?hub_id=1&use_ai_explanation=true"

# Replan route
curl -X POST "http://localhost:8002/api/v1/optimizer/replan?route_id=1&new_stop_id=5&reason=new_pickup&hub_id=1"


CHECKING IF IT WORKS
=====================
After running the optimize command, you should see:
{
  "routes": [...],
  "total_distance_km": <some number>,
  "solve_time_ms": <200-500>,
  "status": "success",
  "explanation": "..." (if AI enabled) or fallback text (if AI disabled)
}

If you see "No active vehicles", run Step 4 (seed data) again.


TROUBLESHOOTING
===============
Issue: "No active vehicles"
Fix: docker-compose exec routing-service python seed_simple.py

Issue: AI explanation is fallback text
Fix: Check AWS credentials in .env and restart services

Issue: "Bedrock call failed"
Fix: Ensure you have Bedrock access to Kimi K2.5 in AWS Console

Issue: Connection refused
Fix: docker-compose logs routing-service (check for errors)


QUICK VERIFICATION
==================
docker-compose ps  # All services should show "Up"
curl http://localhost:8002/health  # Should return {"status":"healthy"}
docker-compose exec routing-service python seed_simple.py  # Seed data
curl -X POST "http://localhost:8002/api/v1/optimizer/optimize?hub_id=1&use_ai_explanation=false"  # Should return routes
